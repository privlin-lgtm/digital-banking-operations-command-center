# ADR-0003: The 12-service fleet is simulated data, not real microservices

## Status

Accepted

## Context

This platform models a 12-service bank fleet (API Gateway, Core Banking API, Payments Gateway, and so on) with a real dependency graph, six months of metric/incident/SLA history, and per-service dashboards. It would be easy for a reader — or a future contributor — to assume these are 12 real deployable services this repository owns.

They are not. There is exactly one real deployable in this system: the BankOps API monolith, backed by one Postgres instance. The 12-service fleet is rows in that same Postgres database, generated by `apps/api/prisma/seed-history/`, standing in for a fleet this platform is built to _monitor_, not services this platform _is_.

## Decision

Keep the simulation explicit rather than trying to make it feel more "real" by, say, splitting it into actual separate processes. The value of the simulation is in exercising the real incident-management, alerting, SLA, and dashboard machinery against a believable six-month operational history — that value doesn't require the fleet to be real infrastructure, and pretending otherwise would be actively misleading in a codebase whose entire subject is operational honesty.

Concretely:

- Prometheus only ever scrapes the one real process. Per-service telemetry for the simulated fleet lives in Postgres (`Metric`, `Incident`, `SlaRecord`), queried directly by the Grafana "Fleet Operations" dashboard via a Postgres datasource — see ADR-0005.
- Documentation (this file, the README, dashboard panel descriptions) says "simulated" wherever the distinction matters, rather than letting a reader infer it.

## Consequences

- Any load-bearing claim about "12 services" (in a dashboard, in a demo, in this README) needs a simulated/real qualifier — dropping it would misrepresent what's actually running.
- A genuine move to real microservices later would be a different, much larger architectural change (service discovery, per-service deployments, real distributed tracing) — this ADR is not a roadmap toward that, just an honest description of what exists today.
